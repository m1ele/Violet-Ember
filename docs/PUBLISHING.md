# Publishing Violet Ember

This document describes the path to a public GitHub release.

## Branches

- `main` is stable.
- `dev` is experimental.
- Feature branches are short-lived and merge into `dev` first.

## Before publishing

1. Run tests.
2. Test install and uninstall on a fresh user session.
3. Test restore from backup.
4. Review `README.md`.
5. Review `CHARTER.md` and `DESIGN.md`.
6. Update `CHANGELOG.md`.
7. Create release notes.

## Release quality rule

Publish only when every file in the repository feels intentional.

Not perfect. Intentional.
